# v0.1.0 验证与交付记录

日期：2026-09-25。环境：macOS ARM64、Docker Desktop / Engine 29.1.3、容器 Node 22.22.0、隔离 NPM 2.16.0。

## 已通过

- TypeScript 类型检查与生产构建。
- 12 项自动化测试：证书通配符范围与过期、端口映射、幂等创建、停用规则冲突、保留未修改字段、外部指纹冲突、编辑回退、归档恢复、超时对账、只读及受保护规则、未知 NPM 版本、凭据加密完整性、认证/Origin/CSRF、容器重建关联和进程重启后的操作恢复（部分测试组合多个断言）。
- 隔离真实 NPM：初始化测试账号、上传本地测试证书、创建与重复提交、局部修改、旧指纹拒绝、回退、归档及恢复。
- 真实链路：使用测试进程显式信任的测试证书完成 TLS 域名校验；NPM → `host.docker.internal:18999` → HTTP 200。
- Docker Desktop 实际服务发现，包含停止容器与宿主机映射端口。
- Docker reader：容器读取返回 200，写请求和未允许端点返回 403，详情不返回环境变量。
- Docker ARM64 镜像构建和 Compose 部署；应用健康检查正常，宿主机仅绑定 `127.0.0.1:3100`。
- 浏览器桌面与 390px 手机视口检查；通过手机尺寸表单创建并编辑隔离测试入口，项目列表与设置页面可用；观察期间无浏览器脚本错误。
- SQLite 一致性备份、完整性检查，以及复制备份后重新打开数据库、解密凭据与恢复规则关联；数据库重开与恢复关联另有自动化测试覆盖。
- 官方 npm advisory 审计：生产依赖 0 项已知漏洞；构建期间完整依赖审计亦为 0。
- GitHub 仓库可见性核实为 PRIVATE。CI 配置包含类型、格式、单元测试、生产构建及两个 Docker 镜像构建；首个提交的远程 CI 全部通过，后续状态以仓库 Actions 为准。

测试证书、测试凭据、数据库、引导密钥、运行环境和备份均不纳入 Git。

## 尚待正式环境验收

- 由用户初始化工具管理员并输入正式 NPM 账号；工具尚未持有正式 NPM 凭据。
- 验证正式账号的规则可见范围与权限；受限账号最小权限组合未实测。
- 明确工具自己的手机管理域名及访问入口。
- 用户选定一个业务项目，创建正式子域名并从真实手机 Tailscale 链路访问。
- WebSocket 选项已能写入 NPM，真实业务 WebSocket 流量尚未单独验证。
- 高并发、长期运行和大规模项目数量不属于本次个人单机版本验证范围。

## 与规划的差异

v0.1 已覆盖核心闭环。自动轮询、自动补偿写入、日志自动清理和更多 NPM 版本适配留待后续。遇到写入不确定性时明确标记并允许人工对账，不自动猜测或覆盖。不要将“本机测试通过”解释为“正式手机链路验收完成”。
