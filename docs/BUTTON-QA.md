## 发现与修复

1. 多端口服务原先默认选择第一个端口，容易绑定错误项目入口。现在必须显式选择；单端口仍自动填充。若编辑时旧端口已不在当前发布列表中，也显示选择提示并阻止提交。无选择时预览显示“请选择端口”。实际选择19082并重新打开编辑验证保留。
2. 此Mac上 Docker Desktop 经宿主机443回连的TLS检查超时，容器直接访问NPM则通过。增加可选 `compose.npm-network.yaml`，本机已启用，检查目标改用NPM容器名。真实DNS/TLS/HTTP检查全部通过，未降低证书校验要求。
3. 浏览器经系统7890代理访问测试域名超时；使用真实DNS、禁用代理的命令行访问返回200。未自动更改全局代理配置，建议为私有域名配置直连。
